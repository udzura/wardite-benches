# Base64 の32文字ループで生じるインタプリタの時間差

4 MiB decode の成功経路について、ディスパッチ、MIR レジスタスロットの読み書き、Wasm 線形メモリのアクセス経路を個別に切り替えた。**単独の短縮はレジスタ経路 33.41 ms、線形メモリ経路 26.47 ms、ディスパッチ削減 14.45 ms。3つを組み合わせると 94.97 ms 短縮し、対照と iwasm の差の49.9%を回収した。**

同じ入力・Wasm・変更前の2エンジンを改めて交互に測ると、配布時と同じ Wardite バイナリで 236.04 ms、iwasm で 48.98 ms（4.82倍）。前回の 327.93 / 69.13 ms と絶対時間に差がある。以下はすべて今回の測定で、前回との間では時間を差し引いていない。[計測区間と Wasm](../README.md)

## 実験

Wardite は `b27b632`、Spinel は `072516af1`、Apple clang 21.0.0 の `-O2`、macOS 27.2.1 / Apple M3 Pro。JIT 無効、MIR workers 8、iwasm 2.4.5 `--interp`。1回のプロセスごとに4,194,320バイトを復号し、ゲストの単調時計で32文字ループを外から囲んだ。

検証用の Wardite には、Spinel が生成した本来の命令ハンドラから、下表の対照を作った。バイトコードが復号関数の全ワードと一致した場合だけ、対象 PC の opcode を検証用の番号に差し替える。分岐先の PC、ゲストのエラー処理、命令のオペランドはすべて維持する。8構成は同じ実行ファイルの起動時に切り替える。

| 記号 | 変えた処理 | 同じ条件で残した処理 |
|---|---|---|
| D | 最大6個の連続する MIR ハンドラをまとめ、1反復の opcode 取得・switch を221回から39回に減らす | 各命令の PC 更新、オペランド取得、レジスタ・線形メモリ操作、safepoint poll、条件分岐。連結箇所にコンパイラバリアを入れ、メモリを介する中間値をコンパイラがまとめて省く効果を抑えた |
| R | 数値レジスタの読出し・書込みに特化した Spinel 配列アクセスを使い、VM が保持するレジスタ配列の一時的な GC root の重複登録を省く | スロット番号、MIR 上の読み書きの回数、ディスパッチ、線形メモリアクセス。範囲と必要な nil・凍結の処理を保持する |
| M | 連続した対象ハンドラで線形メモリの有効なビューを共有し、そのポインタと長さから読み書きする。Spinel のバッファスライスにも対応する | 入力・変換表からの読出し、出力への書込みの数・順序・値。各アクセスの Wasm 境界検査、書込み可能範囲の検査を行い、範囲外などは元のハンドラに戻す。対象外の opcode に戻ればビューを破棄する |

1反復は **221 MIR 命令、スロット読出し421回・書込み272回、線形メモリの1バイト読出し64回・書込み8回**。読出しは入力32文字と32個の変換表エントリ、書込みは 2 バイト×4 と 4 バイト×4。別のカウンタ用ビルドで、174,763反復のディスパッチが **38,622,623 → 6,815,757** となり、どちらも元の38,622,623命令分の処理を実行したことを確認した。M の読出し11,184,832回と書込み1,398,104回はすべて検証用の境界検査を通り、フォールバックは0回、ビュー取得は1回だった。スロット数は Wardite のプロファイラが定義する MIR 上の回数。[カウンタの実測値](audit.json)

## 全8構成

各15回を2系列、計30回のループ時間の算術平均。各ラウンドに全条件を含め、各条件が各実行位置を一度ずつ占めるように並びをずらした。2系列目はラウンド内の順序を反転した。対照は検証用 opcode に付け替えた同じバイナリの元ハンドラ（239.49 ms）。付け替えを行わない検証バイナリは240.44 msだった。差の分母は対照と同時測定の iwasm の差 190.51 ms。

| 有効にした変更 | ループ (ms) | 対照からの短縮 (ms) | iwasm との差の回収率 |
|---|---:|---:|---:|
| 対照 | 239.49 | 0.00 | 0.0% |
| D | 225.04 | 14.45 | 7.6% |
| R | 206.08 | 33.41 | 17.5% |
| M | 213.02 | 26.47 | 13.9% |
| D＋R | 194.12 | 45.36 | 23.8% |
| D＋M | 177.59 | 61.90 | 32.5% |
| R＋M | 168.88 | 70.61 | 37.1% |
| D＋R＋M | 144.51 | 94.97 | 49.9% |

組み合わせで効果が変わる。例えば M に D を加えると 35.43 ms 短縮した。D 単独の 14.45 ms より大きい。3変更の適用順を6通りすべて取って追加効果を平均すると、短縮した 94.97 ms の内訳は次のようになる。

| 変更 | 平均短縮 (ms) | 対照と iwasm の差に対する割合 | 系列 A / B (ms) |
|---|---:|---:|---:|
| D ディスパッチ | 20.84 | 10.9% | 20.25 / 21.43 |
| R レジスタ経路 | 34.67 | 18.2% | 34.79 / 34.54 |
| M 線形メモリ経路 | 39.47 | 20.7% | 39.75 / 39.19 |

この割合は実装変更によって回収できた実時間の配分である。iwasm 側は無改変で、各エンジンの CPU サイクルの内訳やキャッシュミス率は測っていない。D は元のオペランドデコードと safepoint を残し、R はスロットへのアクセスを続け、M は実データにアクセスする。3変更で残った対 iwasm 差は95.53 ms。[各回の測定値](m3-pro.json)

## レジスタへの書き戻し

- 元のアクセサのまま一時 GC root の重複登録だけを外すと 224.94 ms、対照から **14.55 ms 短縮**した。R 単独の 33.41 ms にはアクセス処理の簡略化も含まれる。
- 別の対照 W では、融合済み `I64_BYTE_LOOKUP` の一時アドレス2個がハンドラ外から読まれないことを、関数全体の副表を含む使用箇所から確認した。宛先スロットの取得と書き戻しを **1反復あたり62回**省くと 231.81 ms、**7.68 ms 短縮**。アドレス計算とゲストメモリのロードは引き続き実行する。
- D＋R＋M に W も加えると **138.95 ms**。対照から100.54 ms（52.8%）分の差を回収し、iwasm との差は89.97 ms となった。

## 残った時間差とオペランド取得

追加のバイナリで、P（MIR 命令列からオペランドを取得する処理の簡略化）と A（64ビットの左右シフトを C の符号なし整数演算で実行）を切り替えた。P は同じ位置のワードを境界検査付きで読み、外側のディスパッチが行う第1オペランドの読出しは維持する。A の対象は1反復に左シフト40回、論理右シフト20回。

各構成20回。下表の追加短縮はこのバイナリの D＋R＋M＋W を基準とした。同時に測った対照は244.04 ms、iwasm は48.39 ms。

| D＋R＋M＋W に加えた変更 | ループ (ms) | 追加短縮 (ms) |
|---|---:|---:|
| なし | 136.38 | — |
| P オペランド取得 | 118.20 | 18.18 |
| A シフト演算 | 130.59 | 5.79 |
| P＋A | 112.57 | 23.81 |

追加短縮の大半は、ディスパッチ削減後も各ハンドラに残るオペランド取得で説明できる。この構成でも iwasm との差は64.18 ms 残る。残差の帰属には別の実験が必要となる。[追加実験の各回の測定値](residual.json)

## 再現

wardite-benches で `script/fixtures`、`script/build` を実行し、`build/wardite` に比較対象の Wardite を用意する。Spinel が生成した C の形を利用するため、上記のリビジョンを使う。生成したバイナリは検証専用で、通常の Wardite ツリーに変更を加えない。

```sh
wardite=/path/to/wardite-at-b27b632
wasm=build/rust/wasm32-wasip1/release/examples/base64_codec.wasm
costs=benchmark/base64-decode/costs
out=build/base64-costs
python3 "$costs/build.py" --audit "$wardite" "$wasm" "$out"
python3 "$costs/audit.py" build "$out" "$out/counts.json"
python3 "$costs/run.py" build "$out" "$out/results.json"
python3 "$costs/summarize.py" "$out/results.json"

extra=build/base64-costs-extra
python3 "$costs/build.py" --residual "$wardite" "$wasm" "$extra"
python3 "$costs/run.py" --residual build "$extra" "$extra/results.json"
python3 "$costs/summarize.py" "$extra/results.json"
```

計時はカウンタを組み込まないバイナリで行う。各構成と Wasmtime で、標準入力の全出力が `data-4m.bin` とバイト単位で一致すること、別のバイト列も一致することを確認してから測る。2反復目の各32文字を1文字ずつ不正値に変え、すべての位置で終了ステータスとエラーの位置・バイト値も確認した。
