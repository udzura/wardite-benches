# 4 MiB Base64 decode の時間差はどこで生じるか

Wardite と iwasm のプロセス時間の差の **約91%が Base64 復号本体**、**約91%がその中の32文字単位のループ**で生じた。復号後の出力は 4,194,320 バイト。親プロセスで測った無改変 Wasm の平均は Wardite 369.52 ms、iwasm 80.07 ms（4.61倍）だった。

## 実測

Apple M3 Pro、macOS 27.2.1 arm64、Wardite `b27b632` / Spinel `072516af1`、JIT 無効、`WARDITE_MIR_WORKERS=8`。iwasm 2.4.5 は `--interp`。各構成について2回のウォームアップ後、18回を2系列実行した。系列間で最初のエンジンを交換し、各ラウンドでも交替した。表は両系列を合わせた各36回の算術平均。差の内訳を足し合わせられるよう、同一計測モジュールのプロセス時間を分母とした。

| 計測モジュール・区間 | Wardite (ms) | iwasm (ms) | 差 (ms) | 全体差に占める割合 |
|---|---:|---:|---:|---:|
| 区間計測版のプロセス全体 | 364.86 | 79.77 | 285.09 | 100% |
| 復号本体（transform 呼び出し） | 329.75 | 69.20 | 260.55 | 91.4% |
| stdin の read_to_end | 6.03 | 1.64 | 4.38 | 1.5% |
| stdout の write_all と flush | 1.14 | 0.03 | 1.11 | 0.4% |
| 残り（起動・モジュール準備・終了など） | 27.94 | 8.89 | 19.05 | 6.7% |

復号本体には末尾 LF の除去、出力バッファの確保、`STANDARD.decode` の呼び出しと戻り処理が入る。そのうち、出力先を受け取って復号する `GeneralPurpose::internal_decode` だけで 329.47 / 69.15 ms、差は 260.32 ms だった。

この関数の **32文字を24バイトに復号するループ**にも時計を入れて追試した。ループの外側で2回だけ時刻を読み、ループに戻る分岐は時計を通らない。ここには入力バイト読み出し、変換表の参照、不正値の判定、ビットの組み立てと出力メモリへの書き込みが含まれる。

| ループ計測版の区間 | Wardite (ms) | iwasm (ms) | 差 (ms) |
|---|---:|---:|---:|
| プロセス全体 | 365.28 | 79.90 | 285.38 |
| 復号本体 | 329.97 | 69.19 | 260.78 |
| うち32文字単位のループ | 327.93 | 69.13 | 258.81 |

32文字ループはこの入力で 174,763 反復する。1反復あたり約 1.88 µs / 0.40 µs で、**全体差の90.7%、復号本体の差の99.2%** を占めた。MIR の初回準備に続いて関数内のループに入った後にも差が残る。ディスパッチ、レジスタ操作、メモリアクセスそれぞれの寄与は今回の区間計測からは分からない。

## 測定方法と再現

`instrument.py` は通常の release Wasm を wasm-tools でテキスト化し、解決済みの呼び出し箇所の前後に WASI の単調時計を挿入する。復号関数・入出力・タイマーを付ける箇所が一意であることを検査する。通常の復号命令を維持し、時刻は main の終了後にバイナリで stderr に一括出力する。標準の Rust release ビルドのシンボル名と32文字ループの形を利用する。

`measure.py` は無改変版、区間計測版、ループ計測版のそれぞれについて、計測前に Wardite、iwasm、Wasmtime で出力を参照バイナリとバイト単位で照合する。SHA-256 は全構成で `eade637e7fd39258be5195764439820e40877ab64dfb005964e0d47c10554dbe`。計時は各回新規プロセスで、stdin は入力ファイル、stdout は `/dev/null`、MIR キャッシュ・トレース・プロファイラは無効。計測モジュールの実行順は6通りを循環させた。

同じ入力の別実行で Wardite の `--mir-profile` も確認した。無改変 / 区間計測 / ループ計測の総ディスパッチは 38,632,614 / 38,632,703 / 38,632,715。主要命令の `I64_BYTE_LOOKUP` はいずれも 5,417,653 回、`BR_IF_I64_EQ` は 4,893,367 回だった。時間の内訳はプロファイルを外した同じモジュール内で算出した。

```sh
script/build
script/fixtures
python3 benchmark/base64-decode/measure.py --output build/decode-a.json
python3 benchmark/base64-decode/measure.py --reverse --output build/decode-b.json
```

`--build` で既存の build ディレクトリを使える。Wasm の操作に wasm-tools 1.218.0、出力比較に Wasmtime 49.0.0 を使用した。公開した JSON には各回のナノ秒値、使用したバイナリ、Wasm、入出力の SHA-256 が入っている。[系列 A](m3-pro.json)・[系列 B](m3-pro-reverse.json)

32文字ループ内でディスパッチ、MIR レジスタ、線形メモリのアクセス経路を個別に変えた[要因別の実測](costs/README.md)。

Wardite と Spinel に実装した変更の比較は、[本実装のベンチマーク](ffi.md)にまとめた。
