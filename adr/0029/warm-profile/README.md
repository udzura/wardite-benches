# ruby.wasm の全キャッシュヒット時の内訳

ADR 0029 の 147.65 ms を測った Wardite #89（`3edaf5d`、Spinel `68476ebd3`、`-O2`）と同じ Ruby 4.0.9 で、`--disable-gems -e 'puts RUBY_DESCRIPTION'` を測った。Apple M3 Pro、macOS 27.2.1。MIR2 は 90,800,699 B、スナップショットは 8,250,276 B。新規プロセス、OS キャッシュはウォーム。無改変・計測ビルドを2回ずつウォームアップし、同じキャッシュから順序を交替して各32回起動した。

| 区間（ms） | 中央値 | 算術平均 |
|---|---:|---:|
| MIR2 キー生成、ファイル読み込み・宣言、関数の遅延復元 | 79.51 | 80.83 |
| スナップショットの復元と実行フレームの再構築（遅延 MIR2 を除く） | 44.39 | 44.84 |
| 復元後のゲスト実行と WASI 呼び出し（遅延 MIR2 を除く） | 0.11 | 0.11 |
| その他（Wasm 入力、セクション処理、インスタンス準備、プロセス起動・終了など） | 23.31 | 24.46 |
| 計測ビルドの全体 | 147.36 | 150.24 |
| 対照の無改変ビルドの全体 | 147.32 | 148.01 |

各回の4区間は重複せず、合計が親プロセスの壁時計に一致する。各行の中央値は個別に算出した。MIR2 の内訳の中央値は、Wasm の SHA-256 を含むキャッシュキー生成が 47.37 ms、MIR2 ファイルの読み込み・検査・関数宣言の復元が 25.21 ms、スナップショット復元中の10関数の復元が 6.60 ms、再開後の12関数の復元が 0.15 ms だった。

保存フレームの先頭から復元するコールスタックは10段。最上段の保存 PC 152 の MIR 命令は `CALL_HOST` で、その呼び出し先は Wasm の import 23（`wasi_snapshot_preview1.fd_write`）だった。実行フレーム再構築後から終了までをそのまま計ると、遅延 MIR2 復元込みで中央値 0.26 ms。スナップショットキー生成から実行フレームの再構築までをそのまま計ると 50.98 ms。

## 再現

Wardite `3edaf5d` の作業コピーと Spinel `68476ebd3` を使う。下の `bench` はこのディレクトリの絶対パス、`scratch` は出力先、`wasm` は Ruby 4.0.9 の WASI モジュールを指す。Wardite の作業コピーで次を実行する。

```sh
make spinel BUILD_DIR="$scratch/release"
git apply "$bench/markers.patch"
make spinel BUILD_DIR="$scratch/probe"
python3 "$bench/measure.py" "$scratch/release/wardite" "$scratch/probe/wardite" \
  "$wasm" "$scratch/samples.json"
```

計測パッチは単調時計を読み、ゲスト終了時にまとめて stderr に出力する。MIR2 関数の遅延復元は呼び出しごとに計時して外側の区間から差し引く。時間計測中は `WARDITE_TRACE` を外し、両ビルドの全出力を照合する。トレースありでは環境がスナップショットのキーに入るので、その条件でも別途キャッシュを作ってヒットを確認する。[全サンプルとバイナリの SHA-256](m3-pro.json)
