# ADR 0028 の比較結果

**既定で採用したのは、Base64 decode のエラー位置を分岐の成立時に設定する `exit_copy`。** 4 MiB デコードでは全体時間の短縮を、初回の実行順を逆にした2系列で確認した。整数演算の畳み込み、制御フロー簡約、汎用 DCE、LICM は個別の opt-in とした。

Apple M3 Pro、macOS 27.2.1 arm64、Spinel `072516af1`（`-O2`）、Wasmtime 49.0.0。親は Wardite [`1e66db7`](https://github.com/udzura/wardite/commit/1e66db7257ee058924ddcfc4483e7e83e79d3307)、候補は [`503e250`](https://github.com/udzura/wardite/commit/503e25053259358cb4e6e36bcd4f840301f542df)。Base64 の元データは 262,145 / 4,194,320 バイト、PNG は 256×256 / 1024×1024、篩の上限は 10,000 / 1,000,000。Ruby は `--disable-gems -e 'puts RUBY_DESCRIPTION'` を実行した。[再現手順](README.md)

ディスパッチは 42,302,637 → 38,632,614（8.68% 減）。減った 3,670,023 回はすべて COPY（4,371,311 → 701,288）だった。小入力では関数 43 の検査ブロックを各 10,922 回通る。共有エラー先に対応する定数代入を正常経路から外した結果で、不正な入力では同じバイトと位置でエラーになる。[系列 A](decode-a.jsonl)・[系列 B](decode-b.jsonl)・[基本ブロック上位30件](blocks.json)

## パスごとの動的ディスパッチ

差分は負が削減。LICM 列だけは「既定＋LICM − 既定」、ほかは「対象パス − 無効」。Ruby は起動ごとに命令数が変動するため、下表は同一入力で実行回数が決まるケースを示す。Ruby の単発プロファイルも生データに収録した。

| 対象 | 無効 | fold | cfg | dce | exit_copy | 追加 LICM |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| encode 小 | 2,486,970 | -14 | -2 | 0 | 0 | -9 |
| decode 小 | 2,651,241 | -14 | -1 | 0 | -229,362 | -6 |
| png 小 | 1,771,090 | -16 | 0 | 0 | 0 | -1,125 |
| sieve 小 | 83,489 | -2 | 0 | 0 | 0 | 0 |
| encode 大 | 39,680,807 | -14 | -2 | 0 | 0 | -13 |
| decode 大 | 42,302,637 | -14 | -1 | 0 | -3,670,023 | -10 |
| png 大 | 23,187,595 | -16 | 0 | 0 | 0 | -1,504 |
| sieve 大 | 10,065,613 | -2 | 0 | 0 | 0 | 0 |

1. **fold** は手書き Wasm のインライン加算を定数 1 の RETURN 一命令にできた。実プログラムの大入力では encode/decode 各14回、PNG 16回の削減に留まった。
2. **cfg** は分岐の連鎖・到達不能な区間を取り除けた。動的な削減は大入力で encode 2回、decode 1回、PNG 0回だった。
3. **dce** の汎用パスはこの3ケースのディスパッチを減らさなかった。分岐経路ごとに読まれるかを使った **exit_copy** で decode に効果が出た。
4. **licm** は PNG 大で 1,504 回の削減だったが、全体時間は短縮しなかった。小入力の計数は下表。Ruby では元の式を実行しない経路にも巻き上げた計算が加わった。

| encode | 11 | 14 | 5 | -9 |

| png | 52 | 1,633 | 508 | -1,125 |
